# ASD-STE100 Skill — Simplified Technical English for Agent Output

> Source: https://github.com/danyuchn/asd-ste100-skill
> Collected: 2026-09-17
> Published: Unknown

A Claude Code skill that rewrites dense, ambiguous English into ASD-STE100 Simplified Technical English (STE) — the controlled-language standard the aerospace and defense industry built so aircraft maintenance instructions cannot be misread. Repurposes that discipline for an AI agent parsing another agent's output, a tool description, an error message, or an inter-agent instruction, with no human in the loop to resolve ambiguity. 2.1k stars.

## Why STE, and Why for Agents

STE exists because a misread instruction on an aircraft can kill people, and the intended readers were often not native English speakers with no author to call for clarification. The fix: one meaning per word, active voice, simple tenses, one instruction per sentence, short sentences, no dropped words. An LLM agent parsing another agent's output is in a strikingly similar position — no back-channel, no way to ask "did you mean X or Y?"

## Before / After

Before: "This tool will attempt to synchronize state across the various backends that have been configured, and if a conflict is detected it may resolve it automatically depending on the strategy that has been set, or otherwise it will surface the conflict for manual review."

After: "The tool tries to synchronize state across the configured backends. If it finds a conflict, it reads the configured strategy. If the strategy allows automatic resolution, the tool may resolve the conflict without a user. If the tool does not resolve the conflict, it reports the conflict for manual review."

## What This Skill Does

1. Picks a mode. **Strict** covers procedures, error messages, tool descriptions. **STE-flavored** covers READMEs, PR descriptions, explanatory prose — keeps sentence discipline but not the fixed-vocabulary lockdown.
2. Reads input for meaning.
3. Flags rule violations sentence-by-sentence: ambiguous word choice, complex tenses, passive voice with unclear actor, multi-instruction sentences, oversized noun clusters, dropped words, over-length sentences, phrasal verbs, nominalized actions, semicolons, hedge stacks, marketing adjectives.
4. Rewrites each flagged sentence without dropping any fact, condition, or scope qualifier. If shorter phrasing would lose precision, keeps the longer phrasing and flags the trade-off.
5. Outputs the rewritten text on its own, plus a one-line `Kept as-is:` note when it deliberately left something unsimplified.

The linter checks structural patterns only; it does not compare original with rewrite or verify meaning preservation. It checks semicolons, phrasal verbs, nominalizations, marketing adjectives, passive voice, present-perfect forms, long sentences, synonym rotation, and dangling conjunctions. It does not reproduce ASD's official ~900-word dictionary (the standard is not free to redistribute).

## Installation

```
npx skills add danyuchn/asd-ste100-skill
```

Or clone into `~/.claude/skills/asd-ste100`.

## Usage

Trigger with a request to simplify or clarify English text:
- "Disambiguate this tool description"
- "Rewrite this error message so an agent can't misparse it"
- "Apply ASD-STE100 to this instruction"

## Scope

Built for: agent-to-agent messages, tool/function descriptions, error messages, system prompts, inter-agent instructions. Not built for: creative writing, marketing copy, or anything where voice and nuance are the point. Fixes the form of a text, not its substance.
