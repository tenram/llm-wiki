# gnhf — Good Night, Have Fun

> Source: https://github.com/kunchenguid/gnhf
> Collected: 2026-08-24
> Published: Unknown

gnhf is a ralph / autoresearch-style orchestrator that keeps coding agents running while you sleep — each iteration makes one small, committed, documented change toward an objective. "Never wake up empty-handed." One command starts an autonomous loop that runs until stop is requested or a runtime cap is reached. npm package `gnhf`; macOS/Linux/Windows.

## Quick start

```sh
gnhf "reduce complexity of the codebase without changing functionality"
gnhf "objective" --max-iterations 10 --max-tokens 5000000
gnhf --worktree "task" &   # multiple agents on one repo via worktrees
gnhf --current-branch --push "keep improving this app"
```

Run inside a git repo with a clean working tree.

## How it works

Loop: validate clean git → create/use branch → write prompt.md → build iteration prompt (inject notes.md context) → invoke agent non-interactively → success? commit + append notes.md : reset or repair, maybe wait. Three consecutive failures or a permanent error aborts.

- Incremental commits: each successful iteration is its own unsigned commit (cherry-pickable). Commit failures preserve uncommitted work for the next iteration to repair.
- Failure handling: failed iterations rolled back with `git reset --hard` except commit failures; retryable hard agent errors use exponential backoff; permanent errors (e.g., Claude low credit balance) abort immediately. No-op iterations count as failures.
- Usage-limit waits: when Claude rejects due to exhausted usage windows, the iteration rolls back but doesn't count as failure; gnhf reads the reset time from rate-limit events and retries automatically after the window resets (`--max-rate-limit-wait` caps total waiting).
- Runtime caps: `--max-iterations`, `--max-tokens`, `--stop-when <natural-language condition>` (persists per run for resume).
- Shared memory: agent reads/writes `notes.md` to communicate across iterations.
- Run metadata under `.gnhf/runs/` (gitignored); resume support by re-running on an existing gnhf/ branch.
- Live terminal title with status/tokens/commits; exit summary with elapsed time, iterations, token totals, diff stats, review commands.

## Modes

- Default: creates a `gnhf/<slug>` branch.
- Live Branch Mode: `--current-branch` (+ optional `--push` after each successful iteration); never force-pushes or auto-pulls.
- Worktree Mode: `--worktree` runs each agent in an isolated git worktree under `<repo>-gnhf-worktrees/`, enabling multiple concurrent agents on the same repo. Worktrees with commits are preserved after the run.

## Agents

Seven native agents plus any ACP target (via bundled acpx): Claude Code, Codex, GitHub Copilot CLI, Pi, Cursor CLI, Rovo Dev, OpenCode, `acp:<target>` (e.g. gemini). Config at `~/.gnhf/config.yml`: default agent, custom binary paths, per-agent CLI arg overrides, commit message convention (default `gnhf <n>: <summary>` or conventional preset), maxConsecutiveFailures (3), preventSleep (caffeinate/systemd-inhibit/SetThreadExecutionState).

## Observability

JSONL debug log per run (`.gnhf/runs/<runId>/gnhf.log`) with lifecycle events, elapsed timings, error cause chains; per-iteration JSONL streams. Anonymous telemetry only (GNHF_TELEMETRY=0 to disable).
